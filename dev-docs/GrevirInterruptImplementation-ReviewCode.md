## Findings

**P1 — The selected timer configuration does not control hardware setup.**
Location: [interrupt_allocator.hpp](/Users/owebeeone/limbo/grevir-wz/grevir-peripherals/src/grevir/peripherals/timer/interrupt_allocator.hpp:155), [emit.py](/Users/owebeeone/limbo/grevir-wz/grevir-core/tools/grevir_irqgen/emit.py:130), [AVR example](/Users/owebeeone/limbo/grevir-wz/docs/examples/interrupt-avr/interrupt-avr.ino:15), [ESP32 example](/Users/owebeeone/limbo/grevir-wz/docs/examples/interrupt-esp32/esp_app_base.hpp:49). **Trigger:** AVR declares `pwm_required=true` and selects the `pwm_period` candidate, while the sketch sets `TCCR1A=0` and runs Timer1 in normal mode. The generated installer passes only a source key; ESP32 likewise hardcodes divider and alarm values outside the selected record. **Scope:** shared allocation contract and both named backends. **Classification/provenance:** introduced correctness and interface defect. **Impact:** the checked plan can describe a mode or parameters different from the running peripheral, breaking the single-plan authority and potentially delivering the wrong interrupt behavior. **Remedy:** carry the complete selected configuration into target setup and have the backend apply or verify it before enabling the source. **Closure test:** select two legal modes through changed constraints and demonstrate that emitted setup and target register configuration follow each selected mode; check the AVR PWM claim against the configured mode.

**P2 — Validation does not prove that a binding is offered by the selected target inventory.**
Location: [binding.hpp](/Users/owebeeone/limbo/grevir-wz/grevir-core/src/grevir/interrupt/binding.hpp:51), [emit.py](/Users/owebeeone/limbo/grevir-wz/grevir-core/tools/grevir_irqgen/emit.py:28). **Trigger:** a board allocator returns a `SelectedPlan` with a catalog event and demanded key, but an unrelated owner, configuration, or selector. The C++ validator checks key equality and source consistency; the AVR/ESP32 emitter checks source, entry, and two policy strings, leaving those fields unchecked. The examples also restate request keys in hand-built `Problem` objects ([AVR](/Users/owebeeone/limbo/grevir-wz/docs/examples/interrupt-avr/avr_app_base.hpp:30), [ESP32](/Users/owebeeone/limbo/grevir-wz/docs/examples/interrupt-esp32/esp_app_base.hpp:30)). **Scope:** shared demand-to-binding proof. **Classification/provenance:** introduced correctness defect. **Impact:** a canonical, successfully emitted plan need not correspond to a request in the module closure or a mode actually offered by its owner. **Remedy:** derive allocation requests from the closure and validate every selected record against typed candidate and backend capability metadata, including owner and selector. **Closure test:** compile-time negative cases for foreign owner, non-offered configuration, and non-offered selector, plus a positive closure-derived request.

**P2 — A legal shared-source plan cannot reach firmware.**
Location: [emit.py](/Users/owebeeone/limbo/grevir-wz/grevir-core/tools/grevir_irqgen/emit.py:26). **Trigger:** two events on one physical source satisfy the C++ and JSON checks for common owner, entry, snapshot and acknowledgement policies, distinct selectors, and stable dispatch order. `emit()` then rejects every group with more than one event. **Scope:** shared emitter contract, including the mock gate. **Classification/provenance:** introduced implementation gap against the accepted architecture. **Impact:** validation accepts a plan the build cannot emit, and the specified shared-source dispatch proof cannot complete. **Remedy:** generate one entry with a single status snapshot, defined selector dispatch order, and one acknowledgement policy, or explicitly narrow the accepted plan contract and design documents for this milestone. **Closure test:** end-to-end mock case with two distinguishable events on one source, one registration, and both handlers dispatched in declared order.

**P2 — An undemanded offered event can falsely block allocation.**
Location: [interrupt_allocator.hpp](/Users/owebeeone/limbo/grevir-wz/grevir-peripherals/src/grevir/peripherals/timer/interrupt_allocator.hpp:123). **Trigger:** two requests use distinct timers; the earlier request has no handler but selects an event-capable candidate whose source or entry matches the later, demanded request. The compatibility check treats `used.period_event` as an active binding and rejects the later candidate. **Scope:** shared timer allocator. **Classification/provenance:** introduced correctness defect. **Impact:** a valid application can report a source conflict or no solution even though it would install only one interrupt. **Remedy:** track whether each selected request is demanded and compare source/entry ownership only between active bindings. **Closure test:** the stated two-request case succeeds with one binding; adding a handler for the first request produces the expected conflict.
